Mọi lỗi mà SDK chủ động ném ra đều là `HydraBridgeError` với chuỗi `code` ổn định, `message` dễ đọc và `details` tùy chọn. Hãy rẽ nhánh theo lớp lỗi hoặc mã lỗi, không bao giờ theo nội dung message: message có thể được đổi cách diễn đạt giữa các bản phát hành, còn mã lỗi thì không.

## Các lớp lỗi

| Lớp | Mã lỗi | Được ném khi |
| --- | --- | --- |
| `HydraBridgeError` | bất kỳ | Lớp cơ sở. Cũng được ném trực tiếp cho lỗi kiểm tra đầu vào, lỗi kết nối và lỗi do host báo về. |
| `HydraTimeoutError` | `ERR_TIMEOUT` | Một request hoặc handshake vượt quá timeout, hoặc host báo timeout. |
| `HydraUserRejectedError` | `ERR_USER_REJECTED` | Người chơi từ chối hoặc hủy một yêu cầu của ví. |
| `HydraTransportError` | `ERR_TRANSPORT_FAILED` (mặc định) hoặc mã tùy biến | `init()` chạy ngoài iframe, transport không có window để gửi hoặc đã bị destroy, `postMessage` ném lỗi (`ERR_POSTMESSAGE_FAILED`), hoặc `hostOrigin` bị thiếu hay không hợp lệ. |
| `HydraSecurityError` | `ERR_UNTRUSTED_ORIGIN` | Dùng origin wildcard `'*'` ngoài môi trường được biết chắc là `development` hoặc `test`. |
| `HydraStorageError` | `ERR_STORAGE_UNAVAILABLE` | Storage bị chặn, hoặc host storage relay thất bại, timeout hay đã bị destroy. |

Mọi lớp đều nhận `(message, details?)`, trừ `HydraBridgeError(message, code, details?)` và `HydraTransportError(message, code?, details?)`.

## Mã lỗi

`ERROR_CODES` chứa các mã ổn định, và `ErrorCode` là kiểu tương ứng (nó cũng chấp nhận mọi chuỗi khác):

| Mã | Lớp | Ý nghĩa |
| --- | --- | --- |
| `ERR_TIMEOUT` | `HydraTimeoutError` | Xem ở trên. |
| `ERR_USER_REJECTED` | `HydraUserRejectedError` | Xem ở trên. |
| `ERR_NOT_IN_IFRAME` | `HydraTransportError` (và `HydraBridgeError` từ `ping()`) | Trang không nằm trong iframe, nên không có host shell. |
| `ERR_UNTRUSTED_ORIGIN` | `HydraSecurityError` | Xem ở trên. |
| `ERR_STORAGE_UNAVAILABLE` | `HydraStorageError` | Xem ở trên. Host cũng có thể gửi mã này khi storage của chính nó gặp lỗi. |
| `ERR_BRIDGE_NOT_CONNECTED` | `HydraBridgeError` | `init()` chưa hoàn tất, handshake bị hủy, hoặc client đã disconnect hay bị destroy. |
| `ERR_WALLET_NOT_CONNECTED` | `HydraBridgeError` | Do host gửi: chưa có ví nào được kết nối trong host. |
| `ERR_INVALID_PARAMS` | `HydraBridgeError` | Một tham số không qua được bước kiểm tra (CBOR giao dịch rỗng hoặc không hợp lệ, địa chỉ sai, payload hex sai, orientation hoặc mẫu haptic sai). |
| `ERR_INVALID_RESPONSE` | `HydraBridgeError` | Host trả về giá trị sai dạng (ví dụ change address không đọc được). Với `signTx(..., { mergeWitnesses: true })`, không ghép được witness set của ví vào giao dịch; witness set được giữ trong `details.witnessSet`. |

## Các mã lỗi khác

Các mã này nằm trong `ERROR_CODES` và có thể xuất hiện trên một `HydraBridgeError` (hoặc `HydraTransportError`), trừ `ERR_UNSUPPORTED_METHOD` chỉ do host gửi:

| Mã | Ý nghĩa |
| --- | --- |
| `ERR_TRANSPORT_FAILED` | Mã mặc định của `HydraTransportError` khi không có mã cụ thể hơn. |
| `ERR_INVALID_OPTIONS` | Tùy chọn của client không hợp lệ: không truyền `transport` lẫn `hostOrigin`. |
| `ERR_TRANSPORT_UNAVAILABLE` | Có request được gửi khi không có transport. |
| `ERR_POSTMESSAGE_FAILED` | `window.postMessage` ném lỗi, thường do một giá trị không clone được. Được ném dưới dạng `HydraTransportError`. |
| `ERR_RPC_FAILED` | Host báo thất bại mà không kèm mã lỗi riêng. |
| `ERR_UNSUPPORTED_METHOD` | Do host gửi: host không triển khai phương thức được yêu cầu. |

Các mã do host shell gửi trong một RPC error được chuyển tiếp nguyên vẹn, nên bạn có thể gặp những mã không có trong danh sách này. Hãy coi các mã không biết là lỗi chung. Host dựng trên `@hydraone-sdk/host` trả lời bằng `HOST_ERROR_CODES` (`ERR_USER_REJECTED`, `ERR_WALLET_NOT_CONNECTED`, `ERR_INVALID_PARAMS`, `ERR_STORAGE_UNAVAILABLE`, `ERR_UNSUPPORTED_METHOD`, `ERR_RPC_FAILED`) bằng cách ném `HostRpcError(code, message)`.

## Mẫu xử lý

```ts
import {
  ERROR_CODES,
  HydraBridgeError,
  HydraTimeoutError,
  HydraStorageError,
  HydraSecurityError,
  HydraTransportError,
} from '@hydraone-sdk/core';

export function describeError(err: unknown): string {
  if (err instanceof HydraTimeoutError) return 'Timed out';
  if (err instanceof HydraStorageError) return 'Storage blocked';
  if (err instanceof HydraSecurityError) return 'Untrusted origin';
  if (err instanceof HydraTransportError) return 'Transport problem';
  if (err instanceof HydraBridgeError) {
    return err.code === ERROR_CODES.ERR_USER_REJECTED ? 'Cancelled' : `Error ${err.code}`;
  }
  return 'Unknown error';
}
```

Hãy kiểm tra các lớp con cụ thể hơn trước `HydraBridgeError`, vì chúng đều kế thừa từ lớp này. Bất cứ thứ gì không phải `HydraBridgeError` đều là lỗi trong code của bạn hoặc lỗi runtime, nên hãy ném lại hoặc báo cáo.

## Xử lý từng loại lỗi

- **`ERR_USER_REJECTED`**: không phải là thất bại. Cho phép người chơi thử lại; đừng tự động retry.
- **`ERR_TIMEOUT`**: request có thể đã thành công trên host. Với `submitTx`, hãy kiểm tra trên chain trước khi gửi lại. Các phản hồi đến muộn sẽ bị bỏ qua.
- **`ERR_BRIDGE_NOT_CONNECTED`**: gọi `await client.init()` trước mọi truy vấn ví. Sau `destroy()`, hãy tạo client mới.
- **`ERR_STORAGE_UNAVAILABLE`**: không lưu được dữ liệu. Giữ cho game vẫn chơi được khi không có nó.
- **`ERR_UNTRUSTED_ORIGIN`**: đây là vấn đề cấu hình chứ không phải vấn đề lúc chạy. Hãy đặt đúng origin trong `hostOrigin` thay vì `'*'`.
- **`ERR_INVALID_RESPONSE`** sau `signTx` với `mergeWitnesses`: người chơi đã ký rồi. Tự ghép `details.witnessSet` bằng `applyWitnessSet(cbor, witnessSet)`, hoặc báo lỗi của host; đừng yêu cầu người chơi ký lại một cách mù quáng.

## Serialization và an toàn

`error.toJSON()` trả về `{ name, code, message, details, stack }`. Hãy loại bỏ `stack` và `details` trước khi gửi lỗi tới một dịch vụ bên ngoài nếu chúng có thể chứa địa chỉ ví hoặc token.

Bản thân các message do SDK tạo ra không bao giờ chứa secret, nhưng `details` là dữ liệu tự do và có thể lặp lại những gì host đã gửi.
